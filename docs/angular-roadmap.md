## 1 — Новый дизайн ✅

UI остаётся на Angular Material, меняется только внешний вид.

- ✅ Дизайн-токены: нейтральная гамма в духе ChatGPT, графитовая тёмная тема и белая светлая;
  зелёный акцент (`--color-primary`, `--color-secondary`) и цвета статусов. Material перекрашен через `--mat-sys-*`, привязанные к нашим `--color-*`.
  Тема выставляется inline-скриптом в `index.html` до старта Angular (без мигания), по умолчанию —
  системная.
- ✅ Чистка: старые имена токенов заменены на новые, алиасы удалены. Заглушка аватара в каталоге
  в тёмной теме приглушается фильтром (класс `--placeholder`, на настоящие аватары не влияет).
- ✅ Регистрация: полноэкранная композиция 50/50 без внешней карточки, форма слева и локальная
  фотография студии справа; на узких экранах — только форма. Убраны выдуманные цифры доверия,
  сохранены обе темы, выбор типа аккаунта и вход через Google. Поля не растягиваются по высоте
  при появлении ошибки в соседней колонке; текст полей и плейсхолдеров уменьшен до 14px.
  Под ошибки полей всегда зарезервировано место через `subscriptSizing="fixed"`, чтобы форма
  не меняла высоту при валидации.
  Форма помещается в высоту экрана без прокрутки на стандартных десктопных разрешениях
  (включая 1280×720) и телефонах 375×812; уменьшены отступы, подпись типа аккаунта стоит над
  переключателем, кнопки занимают всю ширину блока. На слишком низких экранах сохранён доступ
  к полям через прокрутку.
- ✅ Общий стиль полей: шрифт и плейсхолдеры 14px, обычный межбуквенный интервал, компактные
  сообщения об ошибках; иконки внутри полей уменьшены до 20px, область нажатия кнопок сохранена.
  Поля не растягиваются по высоте в сетке. На регистрации логотип с
  названием расположен по центру непосредственно над заголовком формы; увеличен отступ под
  заголовком, убран подзаголовок,
  тип аккаунта выбирается двумя равными кнопками с тонким контуром; выбранный вариант выделен
  лёгкой зелёной заливкой и акцентным контуром без сплошной зелёной плашки.
  Кнопки Continue with Google и Create account на регистрации имеют одинаковую высоту 48px.
- ✅ Убраны вводная фраза на странице входа и надзаголовки Account в профиле и Professional
  services в каталоге вместе с их неиспользуемыми стилями.
- ✅ Верхний отступ заголовка каталога уменьшен до 24px на узких экранах и 32px на десктопе.
  Отступ между заголовком с описанием и поиском уменьшен до 20px на всех экранах.

## 2 — Вход через Google 🔄

Схема: Google Identity Services на фронте отдаёт ID-токен → `POST /api/auth/google` на бэкенде проверяет
его (подпись по JWKS Google, issuer, audience = `GOOGLE_CLIENT_ID`, подтверждённый email) и выдаёт наши
обычные access/refresh-токены. Без `googleClientId` кнопка не показывается, бэкенд отвечает `503`.

- ✅ Бэкенд (`apps/backend`): эндпоинт, миграция (`password` nullable, `google_id`), привязка к
  существующему пользователю по email, новый пользователь — с типом из формы регистрации (по
  умолчанию `CLIENT`), `hasPassword` в `UserResponseDto`, установка первого пароля без текущего.
  Тесты на сервис и контроллер.
- ✅ Фронтенд: `GoogleIdentityService` (ленивая загрузка скрипта), `GoogleSignInComponent` на логине и
  регистрации (своя Material-кнопка, поверх неё невидимый iframe Google), «Set password» в профиле для аккаунтов без пароля.
- ⬜ Проверка end-to-end с настоящим Client ID: `googleClientId` в `apps/frontend/src/environments/environment.ts`,
  `GOOGLE_CLIENT_ID` в `.env` в корне.

- ⬜ Аватар — загрузка, замена, удаление; показ в профиле и в сайдбаре.

## 4 — Специалист и бронирование ⬜

- ⬜ Страница специалиста: профиль, активные услуги, часы работы. `GET /specialist-detail/{id}`.
- ⬜ Выбор слота по диапазону дат. `GET /services/{id}/slots?from&to`.
- ⬜ Запись → `PENDING`. `POST /appointments`.
- ⬜ Mock-оплата записи в `AWAITING_PAYMENT`. `POST /appointments/{id}/pay`.

## 5 — Мои записи ⬜

- ⬜ Список записей с фильтром по статусу и датам, пагинацией. `GET /appointments?status&from&to`.
- ⬜ Действия по роли: клиент — оплатить, отменить; специалист — принять, отклонить, завершить.
  Статус обновляется без перезагрузки. `POST /appointments/{id}/accept|reject|pay|cancel|complete`.
- ⬜ Пункт «My bookings» в сайдбаре.

## 6 — Кабинет специалиста ⬜

Только для типа `SPECIALIST`.

- ⬜ Мои услуги: список (включая неактивные), создание, редактирование, деактивация, восстановление.
  `GET /services?specialistId`, `POST/PATCH/DELETE /services/{id}`, `PATCH /services/{id}/restore`.
- ⬜ Часы работы по дням недели. `GET/POST/PATCH/DELETE /working-hours`.

## 7 — Админка пользователей ⬜ (решить, входит ли в объём)

Только для роли `ADMIN`.

- ⬜ Список пользователей: фильтры по роли, типу, активности, поиск, пагинация.
- ⬜ Деактивация, восстановление, жёсткое удаление с подтверждением.

## Сквозное — ошибки ⬜

Делается по ходу фич, а не отдельным этапом.

- ⬜ Нормализация `HttpErrorResponse` в размеченный `AppError`, без `err.error as ApiError` в
  компонентах.
- ⬜ Глобальный error-интерцептор: 5xx, сеть, 403 → тост; ожидаемые ошибки обрабатывает компонент.
